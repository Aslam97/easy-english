## Rate limiting

The API limits how many requests each API key can send.

### Limits

| Plan | Limit |
| --- | --- |
| Standard | 120 requests per minute for each API key |
| Enterprise | 600 requests per minute for each API key |

The limit uses a rolling window of 60 seconds. The window does not reset at the start of each minute. The API counts the requests of the last 60 seconds at the time of each new request.

### Burst

You can send up to 20 extra requests in any window of 10 seconds. These extra requests help when your traffic grows for a short time.

### Check your limit

Every response has the `X-RateLimit-Remaining` header. It shows how many requests you can still send.

### When you are over the limit

If you send too many requests, the API returns HTTP status `429`. The response has the `Retry-After` header. Its value is the number of seconds that you must wait before you send the next request.

### Block of a key

If a key gets three `429` responses within 5 minutes, the API blocks the key for 15 minutes. To avoid a block, wait for the time in `Retry-After` after each `429` response.

### Batch requests

The `/v1/batch` endpoint counts each item as 1 request. One call can have at most 50 items.

### Higher limits

If you need higher limits, write to support@example.com.
