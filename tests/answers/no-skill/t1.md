## Rate limiting

The API limits how many requests each API key can make, so that one client cannot degrade the service for others.

### Limits

| Plan | Limit |
| --- | --- |
| Standard | 120 requests per minute per API key |
| Enterprise | 600 requests per minute per API key |

**Burst allowance:** in any 10-second window, you can send up to 20 requests above your limit.

**Rolling window:** the limit is measured over a rolling 60-second window. It does not reset at the top of the minute. A request you make at 12:00:30 still counts against you until 12:01:30.

### Monitoring your usage

Every response includes an `X-RateLimit-Remaining` header with the number of requests you have left in the current window.

### When you exceed the limit

If you go over the limit, the API returns `HTTP 429 Too Many Requests` with a `Retry-After` header. The header value is the number of seconds to wait before you retry.

```http
HTTP/1.1 429 Too Many Requests
Retry-After: 12
```

### Temporary blocks

If a key receives three `429` responses within 5 minutes, the key is blocked for 15 minutes. During the block, all requests with that key fail. Honor the `Retry-After` header to avoid this.

### Batch requests

`POST /v1/batch` counts each item in the batch as one request. A single call can contain at most 50 items.
