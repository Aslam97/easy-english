Every key press changes `query` state in `SearchPage`, so `SearchPage` renders again, and that re-renders all 2000 `<Row>` components. Three things make it slow:

1. `items.filter(...)` runs on every render, even when `items` and `query` did not change in a way that matters.
2. `<Row>` is not memoized, so React re-renders every row whenever the parent renders.
3. `onSelect={(id) => select(id)}` creates a new function on each render. So even if you wrap `Row` in `React.memo`, the `onSelect` prop changes every time and memo does nothing.

## Fixes

**1. Keep typing responsive.** Use `useDeferredValue` so the input updates at once and the list updates later:

```tsx
const deferredQuery = useDeferredValue(query)
```

If you prefer, you can debounce the query by about 300 ms instead.

**2. Memoize the filtered list.**

```tsx
const filtered = useMemo(
  () => items.filter((item) => matches(item, deferredQuery)),
  [items, deferredQuery]
)
```

**3. Make `Row` skip needless renders.** You need both parts together:

```tsx
const Row = React.memo(function Row({ item, onSelect }: RowProps) {
  // ...
})

const handleSelect = useCallback((id: string) => select(id), [select])

// ...
<Row key={item.id} item={item} onSelect={handleSelect} />
```

`React.memo` only helps if the props stay the same. `useCallback` keeps `onSelect` the same between renders.

**4. Virtualize the list.** With 2000 rows, even a fast render creates a lot of DOM nodes. Use `react-window` so only the visible rows (about 20) are in the DOM:

```tsx
import { FixedSizeList } from 'react-window'

<FixedSizeList height={600} width="100%" itemCount={filtered.length} itemSize={48}>
  {({ index, style }) => (
    <div style={style}>
      <Row item={filtered[index]} onSelect={handleSelect} />
    </div>
  )}
</FixedSizeList>
```

If you do only one thing, do the virtualization, since it cuts the work the most. Steps 1 to 3 are still worth adding because they stop the extra renders.
